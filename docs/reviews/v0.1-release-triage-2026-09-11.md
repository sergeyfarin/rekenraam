# v0.1 Release Reliability Triage — 2026-09-11

This review answers the release-prep question for every open backlog item. It
is a v0.1 reliability gate, not a promise to complete all future product and
maintenance work before tagging.

## Resolved in the freeze change

- **T-55, upgrade coverage:** closed. Released migration checksums are enforced;
  v0.1-to-HEAD schema equivalence and sentinel-data preservation are tested.
- **T-71, interrupted self-check:** closed. An incomplete check is now a visible
  `errored` run with a diagnostic, never an indefinitely `running` row hidden
  behind an older verdict.
- **T-79, request identity:** closed. Each inbound attempt gets a fresh
  server-generated UUID even when a caller supplies or reuses `X-Request-ID`.

## Open items that are not v0.1 reliability gates

- **T-34** is future provider-event production and remains blocked on R15.
- **T-48** is a dependency upgrade blocked upstream; the supported toolchain is
  pinned and working.
- **T-80** is translation completeness. English fallback keeps every workflow
  usable, but native review still needs the owner to select reviewers per
  language; it remains a release-quality follow-up, not a data-integrity gate.

The public-announcement gates in `docs/roadmap.md` are separate from tagging a
self-hosted v0.1 release. Personal-access tokens, signed reproducible binaries,
and adoption assets remain required before a public announcement or marketplace
listing.

## Release decision

No known open item can silently corrupt a v0.1 database through a supported
workflow. Tagging remains contingent on the normal release validation being
green and on the operator resetting any database created before this final
baseline rewrite. The next schema change must be `0002`; `0001` is frozen.
